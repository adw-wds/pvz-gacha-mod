## ⚠️ 先读：跑起来前必须改的地方

为了开源，**作者本机的游戏路径已改从环境变量读取**。直接克隆下来编译，必须先把游戏目录告诉它：

```powershell
# 指向你自己的游戏安装目录（目录里应有 抽卡版PVZ.exe 与 抽卡版PVZ_Data\）
$env:GACHA_GAME_DIR = 'D:\Games\抽卡0.60.0正式版'
```

这一条会同时被下面几处使用：

| 位置 | 用途 |
|---|---|
| `PvzGachaMod/PvzGachaMod.csproj` 的 `<GameDir>` | 引用游戏的 `Assembly-CSharp.dll` 做编译期注入 |
| `安装器/Program.cs` 的 `DefaultGameDir` | 安装器不传参时的默认游戏目录 |
| `修改器面板/GameInfo.cs` 的 `DefaultGameDir` | 面板定位游戏、启动游戏 |
| `注入器/Program.cs`、`API检查/Program.cs` | 找托管程序集 |
| `注册启动点.ps1`、`工具脚本/*.ps1` | 各类脚本的默认目标 |

也可以不改环境变量，改为在命令行显式传参（安装器、注入器、注册启动点都支持传游戏目录）。

**本仓库对着《抽卡版PVZ》0.60.0 开发。** 游戏更新后，被注入的方法签名可能变化 —— 注入器会 `verify` 报告状态，`API检查` 工具可用来核对引用的游戏 API 是否还存在。

## 项目结构

```
PvzGachaMod/     游戏内 Mod（net472，编译期注入 Assembly-CSharp.dll）
共享/            Mod 与面板共用的底层（JSON / 存档哈希 / 纯逻辑 / 指令集 / 诊断）
修改器面板/      外置 WPF 面板（net8.0-windows，深色 Win10 风格界面）
注入器/          Mono.Cecil 注入器（patch / restore / verify，带 .orig 备份）
安装器/          一键安装 / 卸载（内部会调注入器）
API检查/         构建后校验：mod 里引用的游戏 API 是否真实存在
测试/            无框架控制台断言器（不依赖 xUnit/NUnit，离线可跑）
工具脚本/        开发期验证脚本（截图、端到端验证、设置持久化等）
构建.ps1         构建 Mod
构建MOD.ps1      构建 + 落地产物
发布.ps1         打包交付物
注册启动点.ps1   把 Mod 注册为游戏启动项（带 .orig 备份、幂等、支持 -Unregister）
```

## 构建

前置：.NET SDK 8（面板）与 .NET Framework 4.7.2 目标包（Mod）。**先设好 `GACHA_GAME_DIR`**。

```powershell
# 1) 构建游戏内 Mod
.\构建.ps1

# 2) 构建面板（自包含单文件）
dotnet publish 修改器面板\修改器面板.csproj -c Release -o 修改器面板\publish `
  -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true --self-contained true -r win-x64

# 3) 跑离线单元测试（不需要游戏）
dotnet run --project 测试\测试.csproj -c Release
```

安装到游戏（安装器会自动注入并打印注入状态）：

```powershell
dotnet run --project 安装器\安装器.csproj -c Release -- install "$env:GACHA_GAME_DIR"
```

> ⚠️ **改了 `注入器/Program.cs` 的注入规则后，必须重新发布安装器**。
> 安装器是自包含单文件，**规则表是编译期嵌进去的** —— 只重建 Mod 不重建安装器，会出现
> "注入成功但只报 4/5" 这种静默不一致。

## 工作原理

**为什么不用 BepInEx？** 实测本作的 `mscorlib.dll` 被 Unity 链接器**大面积裁剪**，缺少 BepInEx 预加载器依赖的关键反射 API（`Module.GetPEKind`、`Assembly.LoadFile`），预加载器会直接崩溃。因此本作采用**编译期改游戏程序集**的方式，Mod 不依赖任何运行时框架。

三层结构：

1. **启动点**：把 `PvzGachaMod.dll` 登记进游戏的 `ScriptingAssemblies.json` 与 `RuntimeInitializeOnLoads.json`，由 Unity 在启动时调用 `ModBootstrap.Init()`，与场景无关。
2. **IL 注入**：`注入器/` 用 Mono.Cecil 在游戏方法上插入钩子（带 `.orig` 备份；每次都从原始备份重置后再做全量注入，避免旧注入残留）。**注意：本作的 `TcpListener` 等网络类型同样被裁剪**，所以通信不走网络。
3. **通信：文件命令通道** —— 面板写命令文件，Mod 在 `Update` 轮询；Mod 写状态文件供面板读。面板侧带**乐观更新 + 失败通道**：命令被拒会明确回报原因，不会让界面卡在"同步中"。

被注入的方法与诊断埋点（`calls` / `applied` / `errors`）都可在面板的「诊断」页看到 —— `calls=0` 说明注入点没被游戏走到，`applied=0` 说明走到了但没生效。

## 功能清单

33 项，8 个分组（面板里按分组横向 Tab 展示）：

| 分组 | 功能 |
|---|---|
| 抽卡 | 抽卡免费、抽卡档位、卡包全解锁、商店刷新免费、货架自定义 |
| 战斗 | 零冷却、一击必杀、植物无敌、自动收阳光 |
| 僵尸 | 僵尸无法移动、僵尸无敌、魅惑全部僵尸、僵尸必掉金币、僵尸不后退、僵尸血量倍数、僵尸移速倍数 |
| 种植 | 植物极速攻击、植物免疫冰冻、植物免疫爆炸、子弹穿透、植物自带南瓜壳、植物可飞行、植物显示血条 |
| 实体属性 | 僵尸大小、植物大小 |
| 关卡 | 显示僵尸血条 |
| 系统 | 解锁游戏自带菜单、游戏后台运行、游戏速度 |
| 经济 | 金币锁定、金币值、阳光锁定、阳光值 |

设置会持久化到 Mod 目录下的 JSON，重启游戏仍然生效。

## 本仓库不包含什么

- ❌ **游戏本体**的任何文件：`抽卡版PVZ.exe`、`Assembly-CSharp.dll`、`*_Data/`、APK / ipa / app
- ❌ 任何第三方运行时的二进制副本（Mono.Cecil 通过包引用获取，见 [NOTICE](NOTICE)）
- ❌ 打包好的安装包 / 面板可执行文件（请从源码自行构建）

## 参与贡献

欢迎提 Issue / PR。请保持：

- **绝不修改游戏原始文件**：注入必须走 `.orig` 备份机制，可还原
- **绝不发起外网请求**：本工具是纯本地工具，只允许访问 `127.0.0.1`
- **存档哈希算法必须与游戏逐字节一致**，否则会被游戏标记为异常存档
- 非平凡逻辑请抽到 `共享/` 下的纯函数，并补上 `测试/` 里的断言
- 新增功能开关必须三层齐全：**目录（可见可点）→ 设置（能存住）→ 消费点（真有代码读它）**，只有前两层等于假开关
